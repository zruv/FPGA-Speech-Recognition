### **2. How is this working? (Step-by-Step Flow)**

The current workflow focuses on preparing the "brain" (coefficients) for the FPGA.

**Step 1: Simulation & Feature Extraction (MATLAB)**
The `generate_fpga_coefficients.m` script simulates the hardware behavior.
*   It sets system rules: 16kHz sampling rate, 25ms frame length, and 20 Mel filters.
*   It creates the **Mel Filterbank Matrix**: A mathematical grid that maps linear frequencies (from the FFT) to the "Mel scale" (how the human ear perceives sound).
*   *Crucial Step:* FPGAs struggle with decimal numbers (e.g., `0.334`). The script multiplies these numbers by `4096` (2^12) and rounds them to the nearest integer. This converts the data into **Fixed-Point (Q4.12)** format.

**Step 2: Code Generation**
The MATLAB script automatically formats these integer values into VHDL syntax and prints them.
*   **Input:** Calculated filter matrix.
*   **Output:** A VHDL constant array named `MEL_FILTERS`.

**Step 3: Hardware Integration (VHDL)**
The `Mel_Coeff_Pkg.vhd` file now contains generated constants for `MEL_FILTERS`, `HAMMING_WINDOW`, and `TEST_AUDIO_DATA`.
*   The `MFCC_Accelerator.vhd` design file imports this package (`use work.Mel_Coeff_Pkg.all;`) to access these pre-calculated constants.
*   The accelerator will use these constants for operations like windowing and Mel filtering, avoiding complex real-time calculations on the FPGA.

**Step 4: Simulation Setup**
*   The `MFCC_tb.vhd` testbench instantiates the `MFCC_Accelerator.vhd`.
*   It utilizes the `TEST_AUDIO_DATA` constant from `Mel_Coeff_Pkg.vhd` to provide a fixed audio input stream, enabling functional simulation of the accelerator's behavior without external audio files or hardware.
*   The simulation verifies the data flow, especially the **Windowing** stage, and provides a framework for testing other MFCC pipeline stages as they are implemented.
